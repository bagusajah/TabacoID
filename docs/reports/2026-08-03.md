## Context
Audit post-Phase-0: `public/` cuma berisi logo, favicon, dan `.htaccess`. Tidak ada `robots.txt` maupun `sitemap.xml`. Untuk situs CSR SPA (client-side rendering), ini masalah ganda:
1. **Crawler butuh peta.** React SPA render di browser — Googlebot lihat `<div id="root"></div>` kosong di first paint. Sitemap memberi daftar URL eksplisit supaya penemuan tidak bergantung pada link crawling saja.
2. **robots.txt adalah kontrak dasar.** Tanpa ini, setiap crawler berpura-pura default (allow all) tapi gak ada signal eksplisit. Lebih penting: tanpa robots.txt, gak ada tempat nulis `Sitemap:` directive.

## Lessons Learned
- **SPA + SEO = dua masalah berbeda.** React CSR bagus untuk UX tapi jelek untuk crawlability. Sitemap.txt menutup satu celah (penemuan URL), tapi **bukan** menyelesaikan masalah utama (content kosong di HTML source). Itu pekerjaan Phase 1 item 5 (static generation via vite-ssg). Sitemap ini adalah prasyarat — tanpa peta URL, static generation gak akan maksimal.
- **Orphan route = keputusan content, bukan SEO.** `/services` ada di router (`App.tsx`) tapi gak di nav (`site.ts`). Memasukkannya ke sitemap sebelum content decision dibuat = menyesatkan crawler. Lebih baik skip dulu. Ini contoh YAGNI untuk infrastruktur: bangun untuk yang jelas ada, jangan spekulatif.
- **Ponytail rung 4 (native platform) menang.** Gak perlu `next-sitemap`, gak perlu `vite-plugin-sitemap`, gak perlu script generate. Dua file teks di `public/` — Vercel serve apa adanya. Solusi paling lazy dan paling reliable untuk konten yang jarang berubah.
