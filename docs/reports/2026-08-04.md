# Daily Report 2026-08-04

## Engineering Question
"Berapa memory yang bisa dihemat di Orange Pi RK3588 dengan membersihkan proses desktop idle dan membatasi journald volatile growth?"

## Method
Audit seluruh proses di host — identify desktop applet yang berjalan tanpa fungsi server (headless installation), periksa journald configuration untuk volatile journal growth rate. Eksekusi cleanup langsung, ukur before/after memory.

## Findings

### 1. Desktop Applets (Idle Headless Processes)
Host berjalan XFCE desktop namun tanpa monitor terhubung (headless via SSH/xrdp). Tiga proses GUI berjalan tanpa fungsi server:

| Proses | PID | RAM | Status |
|---|---|---|---|
| `nm-applet` | 3774 | 28 MB | NetworkManager GUI frontend, daemon tetap berjalan |
| `blueman-applet` | 3740 | 24 MB | Bluetooth GUI, bluetooth service sudah inactive |
| `update-manager` | 586535 | 184 MB | GUI tray tool, unattended-upgrades menangani security |

**Total waste: ~236 MB (6.6% dari available memory)**

### 2. Stale TUI Sessions (Hermes Dashboard)
Dashboard punya 3 Node.js TUI processes (total ~494 MB) — dua diantaranya idle 12+ jam dari browser tab yang sudah ditutup. Reaper logic ada (30min TTL) tapi WebSocket detach tidak ter-register, jadi reaper tidak men-trigger. Tidak ada code fix untuk sekarang — tapi satu session ternyata sudah ter-clean up setelah kita mulai investigasi (kemungkinan gateway restart).

### 3. Journal Volatile Growth
Storage=volatile (tmpfs/RAM), growth rate ~19M/hr. `RuntimeMaxUse` tidak diset — defaultnya unbounded. Pada board dengan 7.7G RAM, ini bisa menyebabkan memory pressure.

## Measurements

| Metric | Before | After | Delta |
|---|---|---|---|
| Used RAM | 3.5 GiB | 3.3 GiB | -200 MiB |
| Available RAM | 3.9 GiB | 4.1 GiB | +200 MiB |
| Desktop applet processes | 3 (236 MB) | 0 | -236 MB |
| Journal disk cap | Unbounded | 100 MB RuntimeMaxUse | Capped |

## Actions Taken

1. **Killed idle desktop applets:** `nm-applet`, `blueman-applet`, `update-manager` — menghemat ~236 MB
2. **Removed autostart entries:** `~/.config/autostart/` untuk mencegah respawn
3. **Set `RuntimeMaxUse=100M`** di `/etc/systemd/journald.conf` — membatasi volatile journal growth
4. **Restarted `systemd-journald`** — cap aktif segera

## Decision
**Adopt** — perubahan reversible, low-risk, langsung menghemat resource.

## Risk
- Desktop via xrdp masih berfungsi (XFCE panel, wm tetap berjalan), hanya applet tray yang hilang
- NetworkManager daemon tetap aktif, hanya GUI applet yang dimatikan
- Journal cap bisa dinaikkan jika perlu debug verbose

## Lessons Learned
- XFCE headless installation menyisakan ~236 MB GUI waste — pertimbangkan `multi-user.target` untuk eliminasi full desktop
- TUI session cleanup bergantung pada WebSocket detach event — jika browser crash tanpa disconnect clean, session jadi orphan
- Journal volatile storage perlu cap eksplisit di embedded board — default unbounded tidak safe untuk RAM-limited systems
