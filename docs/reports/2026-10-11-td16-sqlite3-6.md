# TD-16 4th revisit — sqlite3 5→6.0.1, critical count to zero

## Engineering Question
TD-16 (dependency-audit debt): the sole remaining critical finding was the
`tar` ≤7.5.20 advisory chain (via sqlite3→node-gyp 11→cacache). sqlite3@6 was
released with `node-gyp` demoted to a clean 12.x peer and `tar` ^7.5.10 in
deps — does the bump clear the critical chain without breaking the suite?

## Method
1. ROADMAP TD-16 (only open item); `npm audit` baseline 13 (1 critical).
2. Verified fix coverage first: `tar` 7.5.22 > 7.5.20, sqlite3@6 engines
   node ≥20.17 (box runs 26.7). Bumped `^6.0.1`, updated
   `allowScripts.sqlite3@6.0.1` (exact pin required — npm warns on ranges).
3. aarch64 wrinkle: sqlite3@6 prebuilt napi binary requires GLIBC_2.38; this
   box is Ubuntu 22.04 (GLIBC 2.35) → `ERR_DLOPEN_FAILED`. Fixed by building
   from source (`npm rebuild sqlite3 --build-from-source`; gcc/make present,
   node-gyp 12 peer installs cleanly).
4. Smoke test: in-memory DB create+select OK. `npm test` → 406/406 green,
   clean exit.

## Findings
- `npm audit` 13 → **6** (0 critical, 3 high, 3 moderate, 0 low); the entire
  `tar`/`cacache`/`make-fetch-happen` chain is gone. Lockfile −800 lines.
- Remaining 6: `aws-sdk` v2 (moderate, needs v3 migration), `uuid` <11.1.1
  (high, breaking; dragged by aws-sdk/sequelize), `braces` (upstream-blocked,
  same as nodemon-chain note from the 3rd revisit).
- Committed `bd7ff0be` (bump) + `84b75fa1` (roadmap row, 4th revisit), pushed
  to `docs/multi-session-tracking`.
- Next candidates: aws-sdk v2→v3 (biggest remaining, also clears the uuid
  copy it drags) or sequelize 6→7.

## Decision
Adopt — critical count is now 0; TD-16 stays open only for the two remaining
breaking majors (aws-sdk v3, sequelize 7) and the upstream-blocked braces row.
